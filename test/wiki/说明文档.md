# MediaWiki + LLM Wiki 知识图谱测试项目 —— 说明文档

## 一、项目目标

在本地把「业务数据库 →` LLM `编译 → MediaWiki 知识库 → 可交互知识图谱」整条链路跑通，
验证 `llm_wiki`（`Karpathy LLM Wiki` 模式，参考仓库` nashsu/llm_wiki`）的核心思想在
MediaWiki 上的落地效果，为后续 MediaWiki 正式上线做技术预演。

**全部技术均为开源免费软件**，本机即可运行，无需任何付费服务。

| Python 胶水层 | Python 3.13 标准库 | PSF | 零第三方依赖（urllib/sqlite3） |

## 三、实现逻辑（LLM Wiki 模式）

参考 nashsu/llm_wiki 的「两步链式摄取」，整体数据流：

```
SQLite 业务库(课程/技能/岗位)
      │  ① seed_data.py 写入种子数据
      ▼
[Step 1 分析] ingest.py：LLM 读取数据库 → 实体/概念/洞见分析
      │         （LLM 不可用时自动降级规则模式，效果不受影响）
[Step 2 生成] ingest.py：为每个实体生成 Wiki 页面
      │         页面内用 [[双链]] 标注实体关系，用 [[Category:xx]] 标注类型
      ▼
MediaWiki 站点（页面 + 内部链接 = 图谱的源码）
      │  ② build_graph.py：调 MediaWiki API 拉取全部页面及其内部链接
      ▼
graph_data.json（nodes = 页面, links = [[双链]], 分类 = 颜色）
      │  ③ 浏览器打开 graph.html
      ▼
ECharts 力导向图（搜索聚焦子图 / 点击节点跳转 Wiki 页面）
```

**核心思想**：图谱不是手工录入的，页面之间的 `[[双链]]` 就是边，页面分类就是节点
类型——图谱从 Wiki 内容中「自动涌现」。更新知识 = 重跑一次摄取 + 构图。

### 模块逻辑详解

**seed_data.py —— 数据准备**
建三张表：course（22 门课）、skill（42 项，分 10 个方向）、position（14 个岗位，含公司/城市/薪资），
以及 course_skill、position_skill 两张关系表。每次运行先清空再插入，保证数据可重复重建。

**ingest.py —— 两步摄取（LLM Wiki 模式的核心）**
1. **Step 1 分析**：从 SQLite 读出全部实体和关系，交给 LLM 做全局分析（技能方向归纳、
   课程体系洞见），结果存为「LLM分析报告」页面；LLM 不可用时跳过分析、正文用规则模板生成，
   流程不中断。
2. **Step 2 生成**：为每个实体拼一个 Wiki 页面——正文是结构化段落（先修课程、涵盖技能、
   对应岗位等），其中所有关联实体都写成 `[[双链]]`，页面底部挂 `[[Category:课程/技能/岗位/概念]]`。
3. **同名消歧**：课程与技能重名（机器学习、深度学习）时课程页标题自动加「（课程）」后缀；
   同名岗位（3 家公司的 Java 开发）合并为一页，公司列表化。
4. **陈旧清理**：对比数据库实体集与站内现存页面，数据库里已删除的实体其旧页面自动删除
   （比较时按 MediaWiki 首字母大写规则规范化，避免 uni-app 被误判）。
5. **幂等**：页面用固定标题 upsert，重复运行结果一致，不会产生脏数据。

**build_graph.py —— 图谱编译**
调 MediaWiki API 分批拉取全站页面的内部链接与分类 → nodes = 页面（含类型、颜色、尺寸、
详情 URL），links = 去重后的 `[[双链]]` → 输出 graph_data.json。附带的统计（各类型数量、
最大连接度）供前端展示。

**graph.html —— 前端渲染**
Vue3 管理状态（视图范围/过滤/搜索/选中节点），ECharts 力导向图渲染。图谱画布固定
2400×1700，放在 overflow:auto 的滚动容器里——**只有图谱区域出现左右/上下滚动条**，
顶栏与左栏不随之滚动；加载完成后自动滚到画布中心。点击节点在左栏显示详情，抽屉里调
MediaWiki parse API 实时预览页面渲染结果。

**数据更新闭环**
数据变化时只需：`python seed_data.py → python ingest.py → python build_graph.py`，
然后点页面上的「刷新图谱」——数据库 → 页面 → 图谱三层自动对齐。

### 与 llm_wiki 原版的对应关系

| llm_wiki（Tauri 桌面应用） | 本项目（MediaWiki Web 版） |
|---|---|
| wiki/ 目录 Markdown 页面 | MediaWiki 页面（可在线编辑、版本管理） |
| [[wiki-link]] 交叉引用 | MediaWiki `[[内部链接]]` |
| sigma.js 图谱视图 | ECharts 力导向图（graph.html） |
| 两步链式摄取（分析→生成） | ingest.py 同样的两步流程 |
| SHA256 缓存跳过未变更文件 | 规则模式下幂等重建（LLM 模式可扩展） |
| Obsidian 兼容导出 | MediaWiki API 可随时导出全部页面 |

│   ├── graph.html            图谱页面（Vue3 + Element Plus + ECharts）

修改页面请改 `web/graph.html`，然后跑 `python deploy_static.py`（或直接重启 `start_wiki.bat`）。

### 启用 LLM 模式（可选）

安装 Ollama 后拉取模型，重启摄取即可获得 LLM 生成的课程简介与全局分析报告：

```cmd
ollama pull qwen2.5:7b
python ingest.py           :: 自动检测 LLM，输出 LLM分析报告 页面
```

也可通过环境变量指向任何 OpenAI 兼容端点：
`set LLM_BASE_URL=http://localhost:11434/v1`、`set LLM_MODEL=qwen2.5:7b`

## 六、当前测试结果

- 数据规模：**22 门课程 / 42 项技能（10 个方向）/ 14 个岗位（同名合并为 10 页，如
  「Java开发工程师」一页列出华为/中兴/工商银行）**，共 80+ 个 Wiki 页面
- 图谱规模：**87 节点 / 389 条边**（含索引、日志等辅助页）
- 标题消歧：课程与技能重名时（机器学习/深度学习），课程页自动加「（课程）」后缀
- 陈旧清理：数据库里已删除的实体，其旧 Wiki 页面在下次摄取时自动删除
- 前端（Vue3 + Element Plus）：顶栏视图切换（课程-技能 / 岗位-技能 / 全部）、刷新、
  导出图片；左栏统计卡片、可点击图例过滤、搜索聚焦子图、节点详情卡片；
  点击「查看 Wiki 页面」弹出抽屉实时预览页面内容（调 MediaWiki parse API）
- 已验证：登录建页、读回、链接查询、图谱数据生成、全部静态资源 200

## 七、后续上线衔接（预演结论）

1. **数据层**：MediaWiki 官方支持 MySQL/MariaDB，上线时把 SQLite 换成 MariaDB（Docker 部署），
   摄取脚本零改动。
2. **导入层**：把 ingest.py 挂成定时任务（数据变更 → LLM 摄取 → 页面更新）。
3. **图谱层**：graph.html + graph_data.json 是纯静态产物，可随时挪到任何前端工程
   （如嵌入你归档的 Vue 平台），或改读 MediaWiki API 实时构图。
4. **扩展方向**：需要结构化查询时装 Semantic MediaWiki 扩展；图谱规模大后把
   ECharts 换成 sigma.js（llm_wiki 同款，百万边级性能）。
