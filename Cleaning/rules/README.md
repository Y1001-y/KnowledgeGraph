# rules/ — 确定性规则表

抽取结果的**后处理**都在这里。原则：prompt 负责"尽量抽对"，本目录负责"确定性地归并和剔除"。
规则表可 diff、可审计、可增量维护，不受模型版本影响。

| 文件 | 作用 | 何时改 |
|---|---|---|
| `alias_map.yaml` | 别名归并：`Mysql/mysql → MySQL`、`k8s → Kubernetes` 等 | 发现同一技能的不同写法各自成键时 |
| `blocklist.yaml` | 后处理黑名单，分 `drop`（剔除）/ `flag`（保留但打标）两级 | 发现误抽词时 |

## 加词条的规矩

1. **先判级再入表**：明确错误的进 `drop`（品牌、福利、指标、任务动词）；
   边界模糊的进 `flag`（AI工具、编程语言、XX经验），人工抽检后再定去留
2. **每条要能回答"为什么它在表里"**：新的误抽词加进对应类，并在文末 `review_log`
   记一行（日期、来源文件、原因）
3. **精确匹配，不做子串**：`测试` 在表里不影响 `性能测试`；
   拿不准用不用子串时，一律不用
4. **alias 只做写法归并，不做语义合并**：`React` 与 `React Native`、`Java` 与
   `JavaScript` 是不同技能；疑似同义放 `pending_review` 人工确认
5. 执行顺序固定：抽取 → alias 归一 → 去重 → blocklist 过滤 → 统计
   （`../scripts/run_extract.py` 已按此实现，两个表都会自动加载）
